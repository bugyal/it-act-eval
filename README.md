# IT Act Eval

Test how well a language model answers Indian tax-law questions: tax calculations, TDS rates and thresholds, payment codes, section mappings, filing dates, and compliance requirements.

The repository includes **questions and reference answers**, a Go evaluation runner, and saved model responses you can inspect without an API key. The largest dataset contains **10,009 questions**, including GST and company-law tasks alongside income tax.

## Choose a dataset

Each dataset is a JSONL file: one question and reference answer per line. Download a file directly from the links below, or clone the repository.

| Dataset | Questions | What to use it for |
|---|---:|---|
| [Original benchmark](data/splits/test.jsonl) (`test`) | 785 | Payment codes, sections, forms, rates, thresholds and compliance bundles; reproducing the original results |
| [Corrected original](data/splits/test-2026-10-11.jsonl) (`test-2026-10-11`) | 785 | The same questions with five gold-answer/type corrections—not 785 additional questions |
| [Application set](data/splits/test-v2.jsonl) (`test-v2`) | 199 | Applying statutory rules to different phrasings and amounts |
| [Expanded set](data/splits/test-v4.jsonl) (`test-v4`) | 620 | Broader compliance tasks, including Hinglish and multi-part questions |
| [Challenge set](data/splits/test-v45.jsonl) (`test-v45`) | 185 | More demanding computation and applied-law questions |
| [Hindi set](data/splits/hindi_eval.jsonl) (`hindi_eval`) | 85 | Hindi questions with typed reference answers |
| **[10k benchmark](data/splits/test-10k.jsonl)** (`test-10k`) | **10,009** | **19 task families**, including TDS, slab tax, thresholds, section mappings, GST and company law |

The split names are dataset identifiers, not model versions. In particular, `test-v45` does **not** mean the answers were generated by a v4.5 model. These sets overlap in scope and sometimes questions; do not concatenate them and report the sum as a unique test set.

See [dataset details and provenance](docs/datasets.md) for schemas, locks, the four 10k shards, and known limitations. These are now **public benchmarks**, not secret holdouts for future blind evaluations.

## Quick start: inspect existing results

You need Git and Python 3.11+. This path makes **no model calls**, needs no GPU or API key, and does not incur inference charges.

```bash
git clone https://github.com/bugyal/it-act-eval.git
cd it-act-eval

# Verify saved results against their selected datasets and reproduce the audit.
python3 scripts/audit.py --manifest data/audit-manifest.json \
  --json-out docs/results-audit.json \
  --md-out docs/results-audit.md --check

# Run the audit's regression tests.
python3 -m unittest discover -s tests -v
```

Read the [results table](docs/results-audit.md) or its [JSON version](docs/results-audit.json). The audit checks each result file separately: dataset membership, question/gold matches, coverage, errors and recorded pass/fail counts. It **recounts saved verdicts**; it does not call models or independently prove those verdicts correct.

## Evaluate your own model

Install the Go version specified in [`eval/go.mod`](eval/go.mod). The runner accepts OpenAI-compatible chat-completion endpoints, including local servers.

Start with a small sample on your own local endpoint:

```bash
cd eval
GOWORK=off go run ./cmd/tax-eval \
  -repo .. -split test-10k \
  -backend custom \
  -base-url http://127.0.0.1:8000/v1 \
  -model YOUR_MODEL_ID \
  -limit 20 -shuffle -concurrency 1 \
  -out results/my-model-smoke
```

Replace the URL and model ID with those served by your model. `-shuffle` uses a fixed seed; a 20-question sample is a smoke test, **not a full benchmark score**.

For the complete 10k run, remove `-limit 20` and write to a new output directory. To choose another dataset, change `-split` to the identifier in the table. A full run sends one request per question and may take substantial time.

For a hosted endpoint, use its base URL and pass `-api-key-env YOUR_KEY_ENV_VAR`, with the credential already set in your environment. Do not put keys in source files or commits. Hosted inference may incur charges.

The runner writes response and grading records to JSONL. Keep each model/run in its own directory, and record the dataset, model ID, endpoint, generation settings and grading protocol with any published score. See [the runner guide](eval/README.md) for resuming interrupted runs, backend options and offline regrading.

### Check your new result file

From the repository root, create a small manifest selecting the exact result and split:

```json
{
  "runs": [
    {
      "path": "eval/results/my-model-smoke/YOUR_RESULT_FILE.jsonl",
      "split": "data/splits/test-10k.jsonl",
      "lock": "data/splits/test-10k.locked.json"
    }
  ]
}
```

Save it as `my-audit-manifest.json`, replacing `YOUR_RESULT_FILE.jsonl` with the actual filename, then run:

```bash
python3 scripts/audit.py --manifest my-audit-manifest.json \
  --json-out my-results.json --md-out my-results.md
```

A limited run will have missing questions; report that coverage rather than presenting it as a completed run. Do not use the legacy pooled `-report` output as a per-run leaderboard.

## How grading works

The included Go grader (`strict-v1`) uses deterministic checks for expected amounts, percentages, sections, dates and other answer entities. It does not use another language model as a judge.

- **Passed / graded** is the score denominator to report, alongside total questions, missing responses, errors and ungraded rows.
- Some answer types need rubrics not supported by this original grader. A complete traversal can therefore have fewer graded answers than questions.
- Later historical workers used extended grading rules. Recounting their saved verdicts is not the same as regrading them with `strict-v1`.
- Matching expected entities does not establish that an explanation is legally correct. The grader may accept contradictory text or reject a reasonable paraphrase.

Dataset locks detect changes to released snapshots; newer release locks cover the complete file, including reference answers. Preserve snapshots and version corrections rather than editing a benchmark in place. [Grading protocols and limitations →](docs/protocols.md)

## Historical Karsastra results

These are saved evaluations of Karsastra, a fine-tuned model. They are not a controlled comparison of all models or a fresh inference sweep.

| Model/run | Dataset and protocol | Passed / graded |
|---|---|---:|
| Initial Karsastra 4B | Original 785 / original grader | 355 / 776 |
| Karsastra v2e | Original 785 / original grader | 469 / 776 |
| Karsastra v4.2 | Original 785 / original grader | 565 / 776 |
| Karsastra v4.4 | Corrected 785 / extended worker | 702 / 785 |
| Karsastra v4.4, same responses regraded offline | Original 785 / `strict-v1` | 698 / 776 |
| Karsastra v4.4 | Challenge set (`test-v45`) / recorded worker verdicts | 93 / 185 in each of two separate runs |
| Karsastra v4.4 | 10k benchmark / recorded worker verdicts, four disjoint shards | 2,151 / 10,002; seven ungraded rows |

**Compare like with like:** the broader datasets have different task distributions, and the later worker is not the original grader. Never select the best response across retries and call the union a single run. The [per-file audit](docs/results-audit.md), [broader-run summary](docs/heldout-results.json), and [protocol notes](docs/protocols.md) explain the denominators.

## Limitations and responsible use

These questions target the law and tax periods stated in each record, not necessarily today's rules. The datasets include generated and adapted questions; reference answers can contain errors and have not all received independent legal review. This is a model-evaluation resource, **not tax advice**.

The original benchmark holds out phrasings while sharing underlying statutory facts with training data; it is not a test of unseen statutory knowledge. Public questions may also appear in subsequent model training. Keep a separate, undisclosed test set if you need a blind evaluation. See the [original split policy](data/splits/README_split_policy.md) and [dataset caveats](docs/datasets.md).
